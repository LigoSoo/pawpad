# tests/ctxdb-recall — ctxdb 회수 훅 회귀셋

`ctxdb-inject` 훅(Claude·Codex 동형)이 **프롬프트 키워드로 과거 맥락을 불러오는** 경로를 지킨다.

**toolkit 개발 자산이다. 배포본에는 포함하지 않는다** — `pawpad-setup.ps1`은 이 디렉터리를 설치처에 쓰지 않는다.

## 왜 필요한가

이 훅은 **깨져도 출력이 `{}`다.** 정상적인 "해당 없음"과 고장이 완전히 같은 모양이라
사람 눈으로는 구분할 수 없다. v2.48이 고친 버그가 설치처에서 **6주간 자동 주입 0회**로
조용히 죽어 있었던 이유가 그것이다(`docs/CHANGELOG_v2.48.md` §1).

훅은 매 프롬프트마다 돌고 배포처가 여러 곳이므로, 한 번 깨지면 전 설치처가 같이 조용히 죽는다.
**회귀셋이 유일한 감지 수단이다.**

## 실행

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tests\ctxdb-recall\run-recall-tests.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File tests\ctxdb-recall\run-recall-tests.ps1 -Hook ".codex/hooks/ctxdb-inject.ps1"
```

| 옵션 | 뜻 |
|---|---|
| `-Hook <path>` | 검사 대상 훅 (기본 `.claude/hooks/ctxdb-inject.ps1`). 경로에 `.codex`가 있으면 codex 런타임으로 판정 |
| `-Filter C7,C13` | 특정 케이스만 |
| `-KeepFixtures` | 실패 분석용으로 임시 픽스처 보존(경로를 출력) |

실패 시 exit 1. 훅을 손대면 **양쪽 런타임 모두** 돌린다.

## 설계 메모

- **픽스처는 커밋하지 않고 매 실행 생성한다.** git이 빈 디렉터리를 추적하지 않아 clean clone에서
  복사 기반 픽스처가 깨진다(review-01 ④).
- **픽스처는 `injectMode: full` 고정.** Codex pointer 렌더링을 벗겨야 회수 로직 자체가 보인다.
  pointer는 C18이 따로 본다.
- **훅 입력 JSON은 `\uXXXX`로 ASCII 이스케이프해서 넘긴다.** 파이프 바이트 인코딩이
  `[Console]::OutputEncoding`에 좌우되는데, 러너를 중첩 프로세스로 실행하면 이게 ANSI로 잡혀
  한글 프롬프트가 깨지고 `tokens=0`이 된다 — 회귀셋 전체가 "한글 회수 실패"로 **오탐**한다(실측).
- **어서션 대상은 주입 컨텍스트의 `ctxdb: ...` 상태줄**이 기본이다. AGENT SYNC 행의 L2 셀을
  `-`로 두는 것도 같은 이유 — 실제 경로를 적으면 주입문에 섞여 어서션을 오염시킨다.

## 검출력 (mutation testing)

"전부 PASS하는 테스트"는 아무것도 지키지 않는다. 수정본에 결함을 하나씩 되심어 각 케이스가
실제로 잡아내는지 확인한 결과(2026-08-27, Claude 훅):

| 되심은 결함 | 잡아낸 케이스 |
|---|---|
| D-1 길이 하한 2 → 3 | C1·C2 + 한글 키워드를 쓰는 전 케이스 |
| D-2 첫 히트 즉시 반환 | **C8** |
| D-3 회수 정규식 `L[234]/` → `L2/` | C7·C12·C13·C16·C17 |
| D-4 포인터 탐색 범위 = 주입 범위(120) | **C5** |
| D-5 폴백을 explicit일 때만 | **C6** |
| 블록 상한 60 → 600 | **C17** |

6/6 검출. D-1·D-3은 파급이 넓어 여러 케이스가 동시에 죽으므로, 개별 케이스의 검출력은
나머지 4종의 **targeted mutation**(단일 케이스만 실패)이 증명한다.

새 케이스를 추가할 때도 같은 절차를 밟는다 — **일부러 깨뜨려 실패하는 것을 먼저 확인**한 뒤 커밋한다.
