## 1. 왜 고쳤나

v2.46이 design에 심어 놓은 최상위 원칙은 **"AI 티 = 불일치"** 하나였다. 간격이 제각각(13px, 17px)이고 radius가 섞이고 컨트롤 높이가 화면마다 다르면 아마추어로 읽힌다 — 맞는 말이고, 정량 체크(`spacing 임의값 0` / `radius 고유값 ≤4` / `컨트롤 높이 ≤3`)까지 붙여 실제로 집행됐다.

문제는 **그 검사가 통과시키는 화면**이었다.

토큰이 전부 스케일 파생이면, 네 개의 KPI 타일이 **모두 같은 크기**여도 통과한다. 주 CTA가 보조 버튼 여덟 개 사이에 파묻혀도 통과한다. 화면의 목적이 3초에 안 읽혀도 통과한다. 정량 체크는 전부 녹색인데 사용자는 어디부터 봐야 할지 모른다 — **일관되게 틀린 위계**다.

이번 릴리스는 그 위에 한 층을 얹는다.

> **위계 정합(Hierarchy Truth)** — 화면은 3초 안에 세 질문에 답한다: **지금 어떤 상태인가 / 다음에 무엇을 하나 / 그러면 무엇을 얻나.** 그 답의 순서가 시각 위계(크기·위치·색)와 **일치**해야 한다.

일관성은 1순위에서 **2순위 수단**으로 내렸고, SKILL.md에 한 줄을 못 박았다: **"일관성이 위계를 이기지 않는다. 토큰 검사만 돌리면 일관되게 틀린 위계가 통과한다."**

두 번째 문제는 **원형 부재**였다. 기존 1단계는 "방향 선언 1줄 + 사유"라는 자유서술이라, 만드는 것이 과업 완료 도구인지 발견형 커머스인지 게임 로비인지에 따라 달라져야 할 구조 결정이 전부 에이전트의 즉흥 판단에 맡겨져 있었다.

## 2. 무엇이 바뀌었나

### 2.1 절차 4단계 → 6단계

| 단계 | v2.46 | v2.51 |
|---|---|---|
| 1 | 방향 + 토큰 시스템 | **제품 원형 분류** (7문항 + 게임 5문항) |
| 2 | 레이아웃 구조 | 의미 기반 토큰 (색 정의 순서 고정·다크 재정의 6항) |
| 3 | 일관성 5축 | **3영역 레이아웃** (상태·맥락·행동) |
| 4 | 검토 | 일관성 5축 (기존 + 3규칙) |
| 5 | — | **상태 전수 12종** |
| 6 | — | 검토 (anti-slop + 원칙 8 + 정량 6 + **최악조건 10**) |

### 2.2 1단계 — 제품 원형 분류 (신규)

7문항으로 좁힌다: 핵심 목표 / 세션당 필수 행동 1개 / 오류 비용·되돌리기 / **색을 콘텐츠가 공급하나 UI가 공급하나** / 화면을 떠나도 유지될 상태 / 신규 vs 반복 사용자 최단 경로 차이 / 필수 범위(접근성·국제화·다크·최소 폭).

게임·라이브서비스면 5문항 추가: 코어 루프 1문장 / 평균 세션 길이 / 영구 vs 기간한정 기능 수 / 재화·진행도 종류 / 톤.

**최대 2개 조합.** 3개 이상 섞으면 위계가 무너진다 — 명시적 상한이다.

### 2.3 원형 16종

**앱·도구 A1~A7**

| ID | 원형 | 핵심 질문 |
|---|---|---|
| A1 | 과업완료형 | 실수 없이 끝낼 수 있는가 |
| A2 | 발견중심형 | 원하는 걸 몰라도 발견하는가 |
| A3 | 반복실행형 | 반복 행동의 비용을 줄였는가 |
| A4 | 지속상태형 | 화면을 옮겨도 핵심 상태가 유지되는가 |
| A5 | 습관형성형 | 오늘 시작하고 내일 돌아올 이유가 있는가 |
| A6 | 조건탐색형 | 감성 탐색이 정확한 확정으로 이어지는가 |
| A7 | **관측진단형** | 지금 데이터가 무엇을 말하고 다음에 뭘 파고들어야 하는가 |

A7은 **신규 추가**다. 데스크톱 분석도구·모니터링 콘솔·로그 뷰어를 커버할 원형이 없었다. 이 원형의 최대 위험을 규칙으로 못 박았다: *"적용 중인 조건을 상시 노출한다. 필터·제외·샘플링은 숨기면 결론을 왜곡한다."*

**게임 G1~G9**: 콘텐츠중심미니멀 / 코지시스템 / 에디토리얼미니멀 / 상태반응 / 액션로비 / 진행루프 / 태스크중심 / 원버튼진행 / 고밀도라이브서비스.

각 카드는 **핵심 질문 / 3영역 배치 / 우선 토큰 축 / 필수 상태 / 설계 규칙 / 대표 실패** 6항으로 통일했다.

### 2.4 2단계 — 의미 기반 토큰

- **이름은 값이 아니라 목적으로**: `blue500` ✗ → `action.primary` ✓
- **색 정의 순서 고정**: 표면 → 텍스트 → 경계 → 의미색 → 행동색 → **브랜드색(마지막)**. 브랜드색을 먼저 잡으면 의미색이 밀려 상태가 안 읽힌다.
- **배분 시작점**: 표면 70 / 브랜드·강조 20 / 행동·상태 10
- **다크는 반전이 아니다** — 표면 3단·그림자→경계선 대체·이미지 명도·상태색·액센트 채도·액센트 위 전경색, **6항 재정의**. 순수 검정 금지.
- 게임은 **economy**(soft/premium/energy) + **rarity**(4단) 축이 **추가**된다(기존 축 대체 아님). `premium`이 `action.primary`보다 강해지지 않게 제한.

### 2.5 3단계 — 3영역 레이아웃 (신규)

플랫폼 무관하게 화면을 먼저 셋으로 나눈다.

| 영역 | 답하는 질문 | 담는 것 |
|---|---|---|
| 상태 | 지금 어떤 상태인가 | 대상 범위·계정·자원·최신성·**활성 조건** |
| 맥락 | 무엇을 보고 있나 | 주 초점 1 + 보조 그룹 2~4 |
| 행동 | 다음에 뭘 하나 | 주 CTA **1** + 보조 + 영구 내비 |

부수 규칙: 텍스트 위계 4단 / **위계 수단 2개 이내**(크기·굵기·색 중 2, 셋 다 바꾸면 소음) / 구분선보다 여백 / **영구와 기간한정을 같은 자리에 섞지 않는다**(임시가 사라져도 레이아웃이 버텨야 한다) / 반복 사용자 단축 경로 별도 설계 / 밀도는 화면 목적별.

### 2.6 5단계 — 상태 전수 12종

기존 4종(로딩·빈·에러·성공) → 12종.
기본 · 눌림/포커스 · 선택 · 로딩 · 완료 · 비활성 · 오류 · **데이터 없음** · **부분 데이터** · **지연/오프라인** · **권한 거부** · 표시환경(큰 글자·회전·다크).

- **색 + 텍스트 + 형태 중 2채널 이상.** 색 단독 금지.
- 실패 화면 = `원인 + 현재 상태 + 대안 + 재시도` 4요소
- 완료 화면은 성공 문구로 끝내지 않는다 — 결과 확인 + 다음 행동
- 알림·배지는 미열람 / 즉시 처리 가능 / 긴급을 구분, **강한 배지 화면당 최대 3개**
- 게임은 컴포넌트 9종 필수 상태표 별도 (주CTA·보조·탭·자원카운터·목표카드·보상카드·이벤트진입점·모달·배지)
- 미정의 칸을 남긴 채 완료 선언 금지 — 해당 없으면 `n/a` + 사유

### 2.7 6단계 — 검토 확장

- **anti-slop 2순위 신설**: "위계 붕괴 = AI 티" (모든 카드가 같은 크기, 주 CTA가 파묻힘, 목적이 3초에 안 읽힘)
- **UI 원칙 6 → 8**: `3초 3질문`, `정직` 추가
- **정량 4 → 6**: `동일 강조도 주 CTA ≤1`, `강한 배지 ≤3`, `색 단독 상태 0건`, `하드코딩 색상 0건` 추가
- **최악조건 10** 신설: 최소 폭 최장 한국어 · 글자 200% · 흑백 · 데이터 0건/과다 · 이미지 없음 · 느린 네트워크 중복 탭 · 다크 · 안전영역 · 다국어 · 키보드 도달
- **한국어 밀도 규칙** 신설: 같은 크기 영문보다 밀도가 높다 → 줄높이·버튼 폭 여유 + 최장 라벨 검증
- **모션 역할 위계** 신설: 피드백 → 공간 관계 → 상태 변화 → 브랜드 장식. 로딩 숨김용 애니메이션 금지.
- **안티패턴 3분류**: 공통 13 / 앱·도구 7 / 게임 9

## 3. 제약 2건

### 3.1 배포 스킬에 레퍼런스 브랜드명 0건 (사용자 지시)

스킬은 `pawpad-setup.ps1`로 외부 배포되므로 **"어떤 앱/게임을 참고했다"가 공개 노출되면 안 된다.** 원형명은 전부 구조 서술로 지었고(`과업완료형`, `고밀도 라이브서비스형`), 출처 URL도 넣지 않았다.

검증:
```
grep -rniE '토스|29CM|오늘의집|캐치테이블|컬리|배달의민족|spotify|duolingo|pinterest|
            airbnb|pokemon|포켓몬|동물의 숲|two dots|brawl|clash|merge mansion|
            royal match|cookierun|쿠키런|nintendo|supercell|https?://' .claude/skills/design/
→ 0건
```

원본 분석 문서 2건(`src/mobile_app_design_analysis_10.md`, `src/casual_mobile_game_ui_ux_design_analysis_ko.md`)은 사용자 승인 하에 삭제했다. 배포본에 포함되지 않는 작업 자료였다.

### 3.2 미러가 SKILL.md만 복사한다

`.agents/skills` 미러 writer(`pawpad-setup.ps1`)는 각 스킬 디렉토리의 **`SKILL.md` 하나만** 복사한다. 하위 디렉토리는 대상이 아니다. 상대 경로 `references/archetypes.md`로 적으면 Codex 쪽에서 참조가 끊긴다.

미러 로직을 고치는 대신 **mockup의 `spec-viewer.html` 선례**를 따랐다 — SKILL.md 안에서 `.claude/skills/design/references/`라는 **절대 경로**로 참조한다. 파일은 한 곳에만 존재하고, 미러 writer는 손대지 않는다. 참조 8곳 전부 절대 경로로 변환했다.

## 5. 미검증 / 잔여

- 🟡 **게임 경로 미검증.** G1~G9·economy/rarity·게임 안티패턴은 작성됐으나 실제 게임 프로젝트에 통과시킨 적이 없다. dblogscope 적용은 A7+A6만 exercise했다.
- 🟡 **`SKILL.md` 16,851 B가 스킬 중 최대**(기존 최대 `resume` 10,036 B). references 분리에도 코어가 큰 이유는 6단계 절차 자체가 늘어서다. 트리밍 여지: 4단계 일관성 5축 표를 `checklists.md`로 내리면 ~2KB 감소.
- 🟡 **다운스트림 반영 필요** — `dblogscope_claude` `-Upgrade` (이 릴리스에서 미실행 시).
- ⚪ dblogscope 목업의 최악조건(최소 폭 960px 조건 칩 줄바꿈 · 글자 200% · 흑백)은 미검증. 목업이 1200×800 고정이다.
- ⚪ dblogscope 토큰 제안 1건 미적용 — `SurfaceSunkenBrush`(표 헤더·입력 배경). 전 화면 영향이라 별도 lane 권장.

# 사후보강 #1 — 재질 축 + 그래픽 컨셉 게이트 (버전 불변, 2026-09-01)

## 왜

§5에 "게임 경로 미검증"으로 남겨 뒀던 것을 실제로 통과시켰다. 게임 프로젝트가 없어 **임의의 캐주얼 퍼즐 로비**(G8 원버튼 진행형 + G9 고밀도 라이브서비스형)를 세워 게이트를 돌렸다.

결과물이 **규칙을 전부 통과했는데도 게임 UI가 아니었다.** 임의값 0, radius 4, 컨트롤 높이 3, 주 CTA 1, 배지 3 — 정량 체크는 전부 녹색인데 화면은 "디자인이 안 입혀진" 평면 앱 UI였다.

원인은 규칙 위반이 아니라 **규칙의 부재**다. 일관성 5축의 `모양`은 `radius / border 두께 / shadow elevation`만 다루는데, 이 셋은 **평면 UI의 어휘**다. 게임 UI는 평면 도형이 아니라 **덩어리(volume)**로 그려지고, 그 덩어리를 만드는 것은 radius가 아니다.

## 신설 ① 재질 축 (material)

모든 표면이 **같은 5층을 같은 순서로** 쌓는다.

| 층 | 역할 |
|---|---|
| ① 아웃라인 | 배경 아트 위에서 요소를 떼어낸다 |
| ② 상단 광택(rim) | 광원 방향을 고정 — 화면 전체가 하나 |
| ③ 본체 그라디언트 | 재질을 입힌다 |
| ④ 하단 립 | 두께감. 눌리면 줄어든다 |
| ⑤ 하드 드롭 | **blur 0** — 흐린 그림자는 앱, 단단한 그림자는 게임 |

파생 규칙 4개: **텍스트 아웃라인**(배경 아트 위 글자는 스트로크 없이 못 읽는다) · **오버행**(리본은 패널 밖, 재화 아이콘은 알약 밖 — 전부 사각형 안에 넣으면 앱이 된다) · **홈은 파이고 채움은 볼록**(진행바 트랙·선택된 탭) · **재질 강도가 곧 위계**(주 CTA가 가장 강하고 상품·보조는 한 단계 낮춘다 — 크기·위치·색에 이은 네 번째 강조 수단).

## 신설 ② 그래픽 컨셉 게이트 (SKILL 2-G)

1·2차본 모두 컨셉을 **에이전트가 임의로** 골랐다. 컨셉이 화면 인상 전부를 결정하는데 묻지 않으면 매번 다른 결과가 나온다.

2단계 진입 시 게임·캐주얼이면 **AskUserQuestion으로 컨셉을 확정한다(생략 금지)**. 컨셉 카드는 `소재 / 아웃라인 / 광원 / 팔레트 / 장식 모티프 / 대표 실패` 6항. 프리셋 3종(자연·목재 / 캔디·젤리 / 수정·마법) + 사용자 자유 입력.

**핵심은 스킨 축 분리다.** 확정된 컨셉은 `--sk-*`만 채우고, `--mat-*`·간격·컨트롤 높이·레이아웃·컴포넌트는 컨셉과 무관하게 불변이다. 컨셉 교체가 **스킨 값 변경만**으로 끝나지 않으면 그건 컨셉이 아니라 **리디자인**이고, 시즌 테마가 늘수록 시스템이 무너진다(G9 "이벤트마다 다른 버튼" 안티패턴과 동형). 그동안 G9에 "신규 콘텐츠는 공통 컴포넌트의 스킨만 변경"이라는 문장은 있었지만 **갈아끼울 대상이 정의돼 있지 않아 집행이 불가능**했다.

의미색과 재화색은 컨셉을 넘나들며 **고정**이다 — 성공/주의/위험이 시즌마다 바뀌면 사용자가 색을 다시 배워야 한다.
