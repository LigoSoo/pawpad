# PawPad v2.55 개선 내용 — 다른 머신 전달용

> 이 파일 하나로 읽을 수 있게 썼다. 경로는 전부 **툴킷 레포 루트 기준 상대경로**다.
> 작성 2026-11-11 · 기준 v2.54(정본과 147파일 해시 일치 확인 후 작업) · 스킬 수 22 불변.
> 상세 근거와 검증 표는 `docs/CHANGELOG_v2.55.md`.

## 1. 한 줄 요약

오래 쓴 설치처에서 **세션을 열 때마다 읽는 파일이 43KB까지 불어나 있었고**, 훅이 막힌 머신에서는 **작업을 끝내도 장기기억(ctxdb)에 저장되지 않았다.** 원인은 읽는 쪽이 아니라 쓰는 쪽 규칙의 구멍이어서, 스킬 6개의 본문만 고쳤다. 훅과 CLAUDE.md/AGENTS.md 템플릿은 그대로다.

## 2. 어떻게 알았나

스킬 22개를 전수 감사하면서 설치처 한 곳(.NET 데스크톱 앱, 소스 307파일, 4개월 사용, 조직 정책으로 훅 전부 차단)을 실측했다.

| 항목 | 실측 |
|---|---|
| 세션 시작 때 읽는 양 | `.ctxdb/INDEX.md` 12.7KB + `_wip.md` 21.7KB(진행 중 lane 0) + `_meta.md` 8.5KB ≈ 43KB |
| INDEX의 AGENT SYNC | 에이전트 2종인데 행 21개("그 앞" 이력 행 누적), 한 줄 최대 649자 |
| `_wip.md` | 종결 메모가 쌓여 182줄 |
| 툴킷 자체 `_meta.md` | 36줄에 24.4KB — 한 줄 최대 2,102자 |
| codemap 크기 상한 초과 | 93파일 중 8개 |
| ctxdb 저장 누락 | 한 세션이 통째로 미기록 → 나중에 재구성 |
| 소스를 건드린 22턴 | codemap 먼저 조회 6 · 없이 14 · 나중에 갱신만 2 |
| 도구 분포 | Bash 417 · Edit 118 · Read 40 · Grep 1 |

감사 결론: **없앨 스킬은 없다.** 고칠 것 9개 중 이번에 6개를 처리했다.

## 3. 원인 네 가지

1. `context-saver`가 "자기 행만 수정"이라고만 했다. 행을 **추가**하는 것은 막지 않았고 INDEX에 크기 상한이 없었다.
2. 상한이 전부 **줄 수**였다(RECENT 8줄, L2 150줄). 한 줄이 수백~수천 자면 상한을 지키면서 양만 는다.
3. `task-done`에 **ctxdb 저장이 없었다.** checkpoint·handoff에는 있다. 8턴 자동 저장은 Stop 훅 전용이라 훅이 없으면 끝낸 작업이 기억에 남지 않는다.
4. codemap 크기 상한을 **Stop 훅만** 집행한다. 훅이 없으면 집행자가 없다.

## 4. 바뀐 규칙

| 스킬 | 바뀐 것 |
|---|---|
| context-saver | AGENT SYNC는 에이전트당 1행(이전 상태는 덮어쓴다). 이력 행은 누가 썼든 삭제 가능, 각 에이전트의 최신 1행만 불가침. `INDEX.md` 전체 8KB 상한 — 넘으면 그 저장 안에서 이력 행 삭제 → 상태 셀 축약 → 키워드 셀 축약, 그래도 넘으면 보고하고 진행 |
| task-done | 7 → **8단계**. `_wip.md`에 종결 메모를 남기지 않는다. `_meta.md`는 RECENT 한 줄 300자·전체 8KB(줄 수와 byte를 함께 잰다), 끝난 NEXT는 `sessions/`로. codemap 파일 byte 점검. **ctxdb 저장 단계 신설**(checkpoint로 이미 저장했으면 L2 블록만 생략, AGENT SYNC는 항상 종결 상태로). lane 없이 한 작업도 기록·저장은 실행 |
| resume | 시작 절차를 CLAUDE.md Session Protocol과 맞춤(ctxdb 단계 추가, codemap은 `_root.md` 우선). 상태표에 `REVIEW_REQUESTED` · `REVIEW_DONE` 추가 |
| codemap | 분할 후(Phase B)에는 다른 문서의 "`_index.md` 갱신"을 leaf + `_root.md` HOT으로 읽는다는 해석 절 신설. HOT은 한 줄 200자, 밀려난 항목은 leaf 등록을 확인한 뒤 버린다. 보관 파일을 새로 만들지 않고, 이미 있는 것은 leaf 대조 후 스텁으로. 훅 없는 환경은 task-done·checkpoint·handoff가 크기 상한 집행 |
| checkpoint | codemap 단계를 Phase A/B 공통 문구로, byte 점검 추가 |
| handoff | 위와 같은 문구로 6번 정리 |

크기 상한 수치는 모든 스킬에서 같다: codemap `_root.md` 2048 / `_index.md` 30720 / 그외 4096 byte.

## 5. 일부러 안 건드린 것

- **CLAUDE.md/AGENTS.md 템플릿** — 섹션 제목이 `-Upgrade` 병합 앵커라 손대면 기존 사용자 업그레이드가 깨진다. 쓰는 쪽만 고쳐도 읽는 양은 준다.
- **훅 스크립트** — 이번 대상은 훅이 없는 환경이다. 훅이 도는 머신의 동작은 그대로다.
- **다른 스킬의 `_index.md` 문구** — 일괄 수정 대신 codemap에 해석 규칙 한 절을 뒀다.

## 8. 남긴 일 (다음 버전 후보)

- **Stop 훅의 8턴 안내문과 CLAUDE.md/AGENTS.md 템플릿의 ON TASK DONE 줄**이 옛 절차를 말한다(`codemap/_index.md 갱신`, ctxdb 저장 없음). 스킬을 실행하면 스킬 본문이 이기지만, 훅 문구만 보고 수동 종결하면 빠질 수 있다. 훅이 도는 머신에서 먼저 볼 항목이다.
- `clarity`: 다섯 차원이 각 8점이면 40점 BLOCK인데 "13점 미만은 질문 금지"라 물을 수 없다. 신규 프로젝트의 Where/Link 예외도 없다.
- `to-prd`: "인터뷰 금지"와 "사용자 확인"이 충돌. 장문 스토리 요구. 설치처에 없는 `CONTEXT.md` 참조.
- `code-delegate`: 부모 컨텍스트 절감을 전체 비용 절감으로 일반화. 백그라운드 서브에이전트 제약 미기재.
- `checkpoint`: 사용량 추정 기준(응답 50회 · 도구 100회 = 50%)이 1M 컨텍스트에 안 맞는다.
- `ctxdb-navigator`: `keywords.md` 분할 관례 미기재. 의미 매칭 폴백의 실사용이 표본에서 0회였다(새 주제가 없었던 것인지는 미확인).
- read-track 훅 대상이 `Read|Grep|Glob`이라 Bash로 읽는 에이전트의 codemap 활용률이 낮게 잡힌다.
- `_wip.md` 템플릿 하단의 사용법·상태표 약 30줄이 매 세션 함께 읽힌다.
- `codebase-map`: 툴킷은 쓰지만 실측 설치처는 4개월간 비어 있었다. 그런데 INDEX 행·L1·키워드 경로는 설치 때 미리 등록된다.

clarity · to-prd · code-delegate 세 건은 Codex 사용량 분석 lane(`codex-skill-token-audit`)의 지적과 겹치므로 그 결론과 함께 처리하는 것이 좋다.
