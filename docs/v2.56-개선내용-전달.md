## 1. 한 줄 요약

codemap이 토큰을 얼마나 줄이는지 처음으로 쟀다. **고칠 위치를 찾는 데 드는 사용량은 codemap이 있으나 없으나 같았다.** 그래서 codemap을 "토큰 절감 장치"가 아니라 **"검색이 막힐 때 보는 길잡이 + 소스에 적혀 있지 않은 함정 기록"**으로 다시 정했다. 이제 소스를 먼저 검색하고, codemap은 정해진 세 경우에만 본다.

## 3. 어떻게 알았나

설치처 1곳(.NET 데스크톱 앱, 소스 307파일, codemap 93파일)에서 쟀다. 사용자 말투로 쓴 요청 3건을 에이전트에게 주고 **고칠 위치만** 찾게 했다. 모델 2종, 조건 3가지, 총 30회다(스킬 없음과 새 방식은 칸마다 2회, 이전 방식은 1회).

- 요청 1: 화면 문구로 검색이 바로 맞는 유형
- 요청 2: 흐름을 따라가야 하는 유형
- 요청 3: 검색어가 넓게 흩어지는 유형

| 평균 토큰 | 강한 모델: 스킬 없음 | 이전 방식 | 새 방식 | Sonnet: 스킬 없음 | 이전 방식 | 새 방식 |
|---|---|---|---|---|---|---|
| 요청 1 | 67,340 | 71,499 | 68,466 | 65,626 | 69,549 | 69,125 |
| 요청 2 | 75,928 | 79,741 | 77,107 | 71,214 | 69,894 | 71,878 |
| 요청 3 | 82,842 | 73,652 | 75,208 | 76,432 | 70,638 | 72,087 |
| 합계 | 226,110 | 224,892 | 220,781 | 213,272 | 210,081 | 213,090 |
| 새 방식 − 스킬 없음 | | | **−2.4%** | | | **−0.1%** |

토큰은 에이전트 기본 컨텍스트를 포함한 값이라, 조건 사이의 차이만 본다.

- **차이가 있다고 볼 수 없다.** 같은 조건을 두 번 돌린 결과끼리 최대 12,576 토큰이 벌어졌다. 표의 요청별 차이(−7,634 ~ +3,499)는 전부 그 안이다.
- **30번 모두 고칠 위치를 같은 곳으로 찾았다.**
- **이전 방식은 헛걸음을 했다.** 소스를 열기 전에 안내 문서 4~5장(9~10KB)을 읽었는데, leaf에 소스 경로가 없어서 6번 모두 leaf를 읽은 뒤 소스를 다시 검색했다. 설치처 leaf 80개 중 소스 경로가 머리에 적힌 것은 19개였다.
- **검색이 헤매는 요청(요청 3)에서는 새 방식이 덜 쓰는 경향**이 있었다. 이것도 편차 안이라 단정하지 않는다.
- **"약한 모델은 소스를 통째로 훑는다"는 가정은 Sonnet에서 재현되지 않았다.** 검색한 뒤 해당 구간만 읽었다.
- **codemap에만 있던 정보는 실측 수치 1건**이었다(기동 대기 시간 대부분이 한 구간에 몰려 있다는 기록). 나머지 함정은 소스 주석에도 있었다.
- **의무 규칙은 지켜지지도 않았다.** 같은 설치처의 실세션 기록에서 소스를 건드린 22턴 중 codemap을 먼저 본 것은 6턴이다.

결론: **없애지는 않는다.** 써도 비용이 늘지 않고, 소스에 없는 함정과 실측 기록은 달리 남길 곳이 없다. "토큰 절감"이라는 설명만 내린다.

## 4. 바뀐 규칙

| 대상 | 바뀐 것 |
|---|---|
| 조회 정책 (CLAUDE.md / AGENTS.md `Retrieval 표시` 절) | "소스 탐색 전 codemap 조회 의무" → **검색 먼저.** codemap은 ① 요청에 검색할 말이 없을 때 ② 첫 검색이 0건이거나 파일 8개 넘게 흩어질 때 ③ 어떤 영역의 파일을 처음 고치기 직전(그 파일명으로 leaf를 Grep해 함정만 확인)에만 본다. Retrieval 줄의 codemap 값은 `hit \| miss \| 불요(검색 직행)` |
| 찾아가는 길 | `_root.md` → 키워드 안내 → 영역 안내 → leaf 순서를 버렸다. 요청의 낱말 2~3개로 `features/`를 Grep해 걸린 leaf 1개만 읽는다. 0건이면 뜻이 같은 낱말로 한 번 더, 그래도 없으면 `keywords.md`. 분할 전(Phase A)이면 `_index.md`를 Grep한다 |
| leaf 규격 | `src:` 파일 경로 / `증상:` 사용자가 실제로 쓰는 말 5~8개 / `함정:` 5줄 이내. 줄 번호는 쓰지 않고, 경위 설명은 ctxdb에 남긴다. 권장 1.5KB, 상한 4096 byte는 그대로. leaf를 읽고도 소스를 다시 검색했다면 그 자리에서 `src:`를 채운다 |
| 갱신 | 새 영역 / 파일 이동·개명 / 파일 삭제 / 함정 발견 / `src:` 오류, 이 다섯 경우에만 쓴다. 그 밖에는 "codemap skip". task-done · checkpoint · handoff에 "건드린 leaf의 `src:` 경로가 실제로 있는지 확인"을 넣었다 |
| HOT 절 | `_root.md` · `_index.md`에서 **없앴다.** 최근 작업은 `_meta.md` RECENT와 ctxdb L2에 이미 있다. v2.55가 넣은 "HOT 한 줄 200자" 규칙은 이것으로 대체된다 |
| stop-check 훅 (ps1 · sh) | 선언 없이 소스를 2건 이상 읽으면 막던 차단을 **껐다**(`retrBackstop` 플래그, 코드와 계측은 남김). 검색으로 바로 가는 것이 정상 경로가 됐기 때문이다. 8턴 안내문과 lane 종결 안내문도 새 절차로 고쳤다(v2.55에서 미룬 것). Codex stop-check는 안내문 1줄만 |
| CLAUDE.md / AGENTS.md 템플릿의 다른 줄 | DoD#5("새 심볼마다 `_index.md` 갱신" → "새 영역·파일 이동·새 함정이 있을 때만") · Session Protocol 7번 · ON TASK DONE 줄(codemap 해당 시 + ctxdb 저장) · ON 8턴 줄 · AGENTS 체크리스트 1줄. 섹션 제목은 그대로 |
| 다른 스킬 | lean-code · clarity · feature-architecture · resume · context-saver의 "`_index.md` 먼저 확인" · "심볼과 1:1 등록" 문구를 새 정책으로 바꿨다 |
| 그 밖의 문서 | HYBRID.md 템플릿 핸드오프 절차 1줄, SKILLS_MANIFEST, README 효과 표(codemap 행을 실측값으로 바꾸고 "토큰 절감 장치가 아니다" 명시), GUIDE · USAGE의 옛 정의 |

본문을 고친 스킬은 9개다: codemap · task-done · checkpoint · handoff · resume · lean-code · clarity · feature-architecture · context-saver(1줄).

사용자가 정한 것 세 가지:
- HOT은 **없앤다.**
- 훅은 **차단만 끈다.** 상태줄 지표는 화면을 확인할 수 있는 머신에서 고친다.
- 기존 leaf는 **조금씩 옮긴다.** 한꺼번에 변환하지 않는다.

## 6. 남긴 일 (다음 버전 후보)

- **상태줄 활용률 지표.** 비율 대신 건수로 보여 주고 빨강 기준을 없앤다. 화면을 확인할 수 있는 머신에서 한다.
- 꺼 둔 차단 코드(`retrBackstop`)를 계속 둘지 정한다.
- Sonnet은 `증상:` 검색이 불안정했다(같은 요청에서 한 번은 바로, 한 번은 네 번 헛짚음). `증상:` 줄을 사용자 말투로 채우는 것이 관건이다.
- "흩어짐" 기준(파일 8개)은 근거 없이 정한 초기값이다.
- 문구만 낡은 곳: 훅 주입 머리말(`symbol registry / HOT`), Codex 포인터 문구(`HOT + prompt keyword`), design · codebase-map 스킬의 "codemap = 심볼 위치". 동작과 충돌하지 않는다(HOT 절이 없으면 건너뛴다 — 코드로 확인, 실행은 미확인).
- lean 설치의 codemap 스킬 부트스트랩 절에 설치되지 않는 스킬 이름(`code-delegate`)이 한 줄 남아 있다(v2.47부터).
- read-track 훅이 Bash로 읽은 것을 세지 못한다(v2.55에서 넘어온 항목).
- 작은 레포용 "codemap 설치 안 함" 옵션.
- 세션 시작 고정 비용(설치처 약 57KB)이 §3 표의 어떤 차이보다 크다. 토큰을 실제로 줄이려면 이쪽이 먼저다.
- v2.55에서 남긴 clarity · to-prd · code-delegate · checkpoint 지적은 그대로다(`docs/v2.55-개선내용-전달.md` §8).
