## 1. 측정 (v2.48 미결의 답)

v2.48 §5는 이렇게 남겨 뒀다: *"오탐률 미측정. 하한을 2자로 낮추면 짧은 일반어 오탐이 늘 수 있다."*
`_meta` NEXT는 `.ctxdb/.state/claude-last-decision`을 며칠 모아 세자고 적어 뒀는데, **그 방법은 성립하지 않는다**:

- `Save-Decision`이 `Set-Content` — 매 프롬프트 **덮어쓰기**. 파일은 항상 2줄(세션 id + 최신 1건).
- 기록에 **프롬프트도 매칭 키워드도 score도 없다** → 사후에 "관련 없는데 loaded"를 가릴 수 없다.
- 세션 dedupe가 같은 ref 재매칭을 `already-loaded`로 삼켜 세션당 표본이 사실상 1건.

대신 **transcript 리플레이**를 썼다. `~/.claude/projects/*/*.jsonl`에는 과거 프롬프트가 그대로 남아 있다.
이걸 실 `.ctxdb/INDEX.md` + 실 훅에 다시 먹이면 제품을 건드리지 않고 그날 숫자가 나온다. 도구: `tests/ctxdb-fpr/`.

| 코퍼스 | INDEX | n | loaded@CJK2(현행) | loaded@CJK3(v2.47 동작) |
|---|---|---|---|---|
| toolkit 자기 코퍼스 | pawpad-toolkit | 54 | 20 | 12 |
| off-domain 음성대조 (TodayQuest/A1Mini/3DPrinter/kingdom) | pawpad-toolkit | 61 | **3** | **3** |
| TeamPitch 자기 코퍼스 | TeamPitch_2.0 | 7 | 2 | 2 |

**수정 전 오탐률: 122건 중 9건 = 7.4%** (loaded 25건 대비 36%, 정밀도 64%). 오탐 1건당 평균 66줄 주입.

### 1-1. CJK 2자 하한은 무죄

- off-domain 61건에서 **하한 2와 3의 판정이 완전히 동일**(차이 0건). 2자 하한이 무관한 프롬프트를 새로 끌어온 사례가 **0건**이다.
- 하한 3으로 되돌리면 toolkit에서 8건이 사라지는데 **그 중 6건이 정탐**(`로고`·`랜딩`·`회전` → brand-docs). 순손실.
- 실제 오탐 9건의 유발 키워드는 **전부 3자 이상**: `프롬프트`(5) · `테스트`(1) · `skill`(1) · `home`(1). 2자는 애매 2건(`스킬`)뿐.

의심의 방향이 틀렸다. v2.48이 "짧아서 위험하다"고 본 지점은 오히려 회수를 살리는 쪽이었다.

### 1-2. 진짜 원인 3종

| # | 원인 | 실례 |
|---|---|---|
| **F-1** | `Find-L1Match`가 키워드 셀을 `[,\s/\|]+`로 split — **공백까지 구분자**라 `점검 프롬프트`로 등록해도 `점검`·`프롬프트`가 각각 독립 키워드가 된다 | "…뭐라고 **프롬프트**를 쓸까?"(주제=codemap 백필) → `domain-skill-audit` 적재 |
| F-2 | 도메인 식별력 없는 일반어가 키워드로 등록돼 있다 (`테스트`·`조사`·`제거`·`후보`) | "에뮬레이터로 **테스트** 진행해"(타 프로젝트) → `domain-ctxdb-recall` 적재 |
| F-3 | score=1을 임계값 없이 채택 | 오탐 9건 전부 |

toolkit INDEX가 유독 취약한 건 도메인이 "이 툴킷 자체를 만드는 일"이라 키워드가 **작업 동사·메타 용어**(`프롬프트`·`점검`·`조사`)이기 때문이다.
TeamPitch INDEX(`클럽`·`회비`·`출석`)처럼 사물명사 위주면 같은 하한에서도 오탐이 적다.

## 2. 변경 — F-1만 수정 (훅 4표면)

`Find-L1Match`의 셀 분해를 두 단계로 나눈다.

```
before: $keywordsCell -split "[,\s/|]+"      # 공백도 구분자 → `점검 프롬프트` = 점검 + 프롬프트
after : $keywordsCell -split "[,|/]+"        # 항목 분리
        항목 안 낱말이 1개  → 종전대로 토큰 매칭
        항목 안 낱말이 2개+ → 구(句). 원문에 통째로 있어야 1점
```

- 구 매칭은 프롬프트 원문(`$promptFlat`, 공백 1칸으로 접음) `Contains` — 조사/어순 변형은 포기하고 오탐 제거를 택했다.
- 시그니처가 바뀐다: `Find-L1Match $IndexLines $PromptTokens $Prompt`. 호출부 2곳(런타임별 메인 흐름) 동시 수정.

### 2-1. 기각한 대안 2종 (실측으로 폐기)

| 안 | 회귀셋 | 정탐 | 판정 |
|---|---|---|---|
| F-3 `score>=2` 하드컷 | – | **16 → 8** | 정탐 절반 소실. score=1 구간에 정탐 7·오탐 7이 섞여 있어 개수로는 분리 불가 |
| F-3 차등 주입(score=1이면 L1만) | **6/20 PASS (14 FAIL)** | – | `C1 로고 어떻게 만들었지`가 `narrow`로 떨어진다. **실 INDEX에서 score=1이 정상 회수의 다수 경로**라 v2.48의 회수 복구를 되돌린다 |

같은 낱말(`테스트`·`스킬`)이 한쪽에선 정탐, 다른 쪽에선 오탐으로 나온다 — **히트 개수만으로는 원리적으로 분리할 수 없다**는 게 데이터의 답이었다.

## 4. 검증

- **회수 무손실**: 회귀셋 `tests/ctxdb-recall` Claude **20/20 PASS**(+1 SKIP) · Codex **21/21 PASS**. 픽스처 키워드 셀이 전부 단일 낱말이라 구 규칙 영향 없음 = 기존 계약 유지 확인.
- **오탐 감소**: 동일 코퍼스 122건 재측정 — **loaded 25 → 20, 오탐 9 → 4, 정밀도 64% → 80%, 오탐률 7.4% → 3.3%**.
- **판정이 바뀐 5건은 전부 오탐**, 정탐 변화 **0**:
  ```
  "…codemap이 프로젝트 시작부터 하지 않아서…"            skill-audit → 무주입
  "code-delegate로 위임해서 백필 돌리는 프롬프트 작성해"   skill-audit → 무주입
  "프롬프트는 /checkpoint 한뒤 /clear 후 진행하겠다"       skill-audit → 무주입
  타 프로젝트 타워디펜스 구현 요청 x2                      skill-audit → 무주입
  ```
- PSParser 0 (setup + 훅 2) · self `-Upgrade` 0 failed · live == embed.

### 4-1. 하네스 자체의 함정 (실제로 밟은 것)

1. **PS 5.1 `ConvertFrom-Json`이 JSON 배열을 파이프라인에서 풀지 않는다** — `@()`로 감싸면 "배열 하나를 담은 1원소 배열"이 되어 코퍼스 122건이 **1건으로 접혔다**. 그대로였으면 오탐률이 0%로 위장됐다.
2. **프롬프트마다 새 session_id 필수** — 아니면 2번째부터 전부 `already-loaded`가 되어 역시 0% 위장.
3. **ASCII 이스케이프 JSON** — 회귀셋과 같은 이유(파이프 인코딩이 중첩 프로세스에서 ANSI로 잡히면 tokens=0).

세 함정 모두 **증상이 "오탐 없음"** 이라 성공처럼 보인다. 측정 도구의 실패가 좋은 결과로 위장되는 방향이라는 게 이 작업의 교훈이다.

## 5. 비고 / 미결

- **남은 오탐 4건은 코드가 아니라 데이터 문제**(F-2). `테스트`·`스킬`×2·`home` — 각 설치처 INDEX에서 식별력 없는 낱말을 빼야 한다. 훅으로 일반어 목록을 내장하면 도메인마다 정답이 달라 오히려 위험하다.
- **라벨링은 단일 판정자**(Claude). 애매 3건은 보수적으로 오탐 계상했다. 다른 판정자면 오탐률이 4.9~7.4% 사이에서 움직인다.
- **코퍼스 편향**: toolkit 54건은 이 툴킷을 만드는 대화라 주제가 INDEX와 겹치기 쉽다. off-domain 61건이 그 보정이다.
- **구 매칭은 표기 변형에 약하다**. `점검 프롬프트`는 잡지만 `프롬프트 점검`·`점검용 프롬프트`는 못 잡는다. 회수 손실은 실측 0건이었으나 INDEX 작성 시 어순을 실사용에 맞추는 편이 좋다.
- **재측정 절차**: `tests/ctxdb-fpr/README.md`. 매칭 로직을 건드릴 때마다 회귀셋(재현율)과 FPR(정밀도)을 **둘 다** 돌린다 — 한쪽만 보면 이번처럼 정탐을 반토막 내는 안이 "개선"으로 보인다.
