## 1. 왜 만들었나 (측정된 사고)

설치처 TodayQuest(Flutter/Android)에서 실기기 QA를 돌리다 **5시간 사용 한도가 그 세션에서 소진**됐다.
사용자가 이상을 감지하고 테스트 기기를 분리해서 멈췄다.

- 방식: `screencap → 이미지 read → 좌표 계산 → adb input tap → screencap → …` (흔한 UI 자동화 루프)
- 생성 **PNG 98장(21MB)**, 그중 **약 50장을 컨텍스트로 read**
- 같은 세션의 코드 수정·테스트·빌드(analyze/test 941건 · APK 2회)는 **비용에서 미미**했다

### 메커니즘 — 지배항은 이미지 크기가 아니라 재전송
- 에이전트는 도구를 호출할 때마다 **그때까지의 대화 전체**를 다시 보낸다.
- 따라서 읽은 이미지 1장은 **그 뒤의 모든 호출에 계속 실려 나간다**.
- 비용 ≈ `이미지 수 × 남은 호출 수`. 캐시는 단가를 낮출 뿐 이 **형태**를 바꾸지 않는다.
- QA는 도구 호출이 가장 많은 작업(탭·스와이프·대기·판독)이라 이 곱이 가장 크게 터지는 자리다.

### `qa-delegate`(위임)는 기각했다
처음 나온 제안은 `code-delegate`처럼 서브에이전트에 넘기자는 것이었다. 거절 근거:

- 서브에이전트는 독립 컨텍스트라 **부모는 깨끗해진다**. 그러나 같은 이미지 루프가 **서브 안에서 그대로 탄다**.
- 사용량 한도는 부모/자식을 구분하지 않는다 → **비용이 안 보이는 곳으로 숨을 뿐 다시 소진된다**.
- `code-delegate`가 통한 이유는 위임 자체가 아니라 **넘길 설계가 이미 문서로 있어 주고받는 양이 작았기** 때문이다. QA는 정반대로 본질이 "화면을 계속 들여다보는 것"이라 위임해도 양이 안 준다.

→ 그래서 **위임 스킬이 아니라 검증 프로토콜 스킬**이다. 위임은 "프로토콜을 지킨 뒤에만 의미 있는 선택 모드"로 격하했다.

## 2. 편입 전 실측 — 원안 결함 6건

제안 문서는 `uiautomator dump`를 **1순위 채널**로 두었고, 그 명령이 원저자 환경에서 **실증되지 않았다**고 정직하게 남겨 두었다.
그대로 넣지 않고 에뮬레이터(**Android 16 / 1080x2400**)에 설치처의 실제 `app-debug.apk`를 깔아 확인했다. 결과 6건을 고쳤다.

| # | 관측 | 조치 |
|---|---|---|
| 1 | Flutter 홈에서 `uiautomator dump` **12/12 실패** — `ERROR: could not get idle state.` (plain 6 + `--compressed` 6, `window_animation_scale 0` 적용 후에도). 같은 기기의 **네이티브 설정 앱·런처는 성공** | dump를 **4순위로 강등** + **화면 1회 프로브**(3회 실패 시 축소 스크린샷으로 전환, 매 화면 재시도 금지, 판정은 queue 헤더에 1줄 기록) |
| 2 | 유일하게 성공한 1회 dump(25노드·10.6 KB)도 **앱 문자열 0건** — `content-desc`의 내비 라벨(`홈`·`설정`)만. 제안서 예시 문자열(`2/4단계` 등)은 하나도 안 잡혔다 | "**dump가 성공해도 기대 문자열이 없으면 판정 근거로 쓰지 않는다**" 명시 |
| 3 | **Git Bash 경로 변환**: `adb shell uiautomator dump /sdcard/ui.xml` → 실제로는 `UI hierchary dumped to: /Files/Git/sdcard/pc_test.xml`. 기기에 파일이 없고, 뒤이은 `cat /sdcard/ui.xml`은 **이전 세션이 남긴 옛 파일**을 읽는다 → **다른 화면으로 PASS 판정**(실패보다 나쁘다) | 🔴 **기기 경로는 `//` 로 시작**(로컬 경로는 그대로) + **dump 전 옛 파일 삭제** 규칙. 회피 실증: `adb exec-out cat //sdcard/x.xml > 로컬` |
| 4 | 에이전트 Bash 도구는 호출 간에 **변수·함수를 보존하지 않는다**(cwd만 유지, 실측). 원안의 `D=<serial>`·`dump()` 헬퍼는 **다음 호출에서 소멸** | 🔴 **스니펫 자기완결 규율** — serial·패키지를 매 호출에 다시 쓴다 |
| 5 | 채널표에 **기기 자동화 테스트가 없다**. 설치처는 이미 `pubspec.yaml` dev_dependencies + `integration_test/` 보유 | **1순위로 신설**(결정적·반복 가능·이미지 0) |
| 6 | "크롭·축소해서 읽는다"에 **명령이 없어** 에이전트가 원본을 read한다 | .NET 리사이즈 스니펫 제공(ImageMagick 불요). 실측 **1,476 → 354 토큰**, 화면 글자 판독성 유지 |

### 실측 단가 (같은 화면 1개 판독)
| 컨텍스트에 들이는 것 | 실측 크기 | 추정 토큰 |
|---|---|---|
| `grep -c` 어서션 1건 | 1줄 | ~10 |
| dump에서 text만 필터 | 479 B / 21줄 | ~250 |
| 스크린샷 **32% 축소**(346x768) | 84 KB | ~354 |
| 스크린샷 원본(→706x1568로 리사이즈됨) | 217 KB | ~1,476 |
| 🔴 dump **원문** 투입 | 29,356 B | ~8,000 |

→ 절감은 dump를 쓰는 행위가 아니라 **걸러내는 행위**에서 나온다. XML 원문을 들이면 **스크린샷보다 5배 비싸다** — 그래서 "원문 투입 금지"가 🔴 규칙이다.

### 정직하게 남긴 미검증
- **노트8(Android 9)에서의 dump 거동은 확인 못 했다**(그 기기 없음). 위 12/12 실패는 Android 16 에뮬레이터 실측이다.
- 실패 원인을 "Flutter 상시 애니메이션"으로 특정한 것은 **정황 근거**(네이티브 설정·런처 성공 / Flutter 홈 실패)이지 분리 실험이 아니다.

## 3. 스킬 내용

`.claude/skills/device-qa/SKILL.md` (미러 `.agents/skills/device-qa/SKILL.md`)

- **검증 채널 우선순위**: 기기 자동화 테스트 → `logcat`/`dumpsys` → 앱 DB → `uiautomator dump` → **축소 스크린샷** → 원본
  - 🔴 1~4로 판정 가능한 것을 5·6으로 하지 않는다. "라벨이 맞는지"는 4번, "그 라벨이 잘렸는지"는 5번, "색이 맞는지"는 6번.
- **어서션 먼저**: 화면 보기 전에 기대 문자열/조건 목록 + **항목별 채널**을 적는다. 5·6번밖에 못 적는 항목이 절반을 넘으면 자동화 테스트로 내릴 수 있는지 먼저 검토.
- **셸 규율 4종**(위 결함 3·4에서 도출): 자기완결 스니펫 / 기기 경로 `//` / 덤프 원문 금지 / dump 전 옛 파일 삭제
- **스크린샷 예산제**: 세션 8장 + 사유 + **읽기 전 32% 축소** + 종료 시 삭제
- **안전 가드**: 블라인드 연속 탭 금지 · 탭 금지 라벨(`계정 삭제`·`데이터 초기화`·`로그아웃`…) · 파괴적 조작 사전 확인 · `mWakefulness` 확인(화면 꺼진 채 쏜 탭은 통째로 유실된다)
- **위임 모드(선택)**: 반환은 `PASS/FAIL + 근거 1줄`, XML·스크린샷 반환 금지. "총 토큰은 크게 안 준다"를 본문에 명시.
- **산출물**: lane `## Verification Evidence`에 바로 붙는 블록 형식 — 기존 **DoD 7번**을 채우는 구조(DoD 항목 추가 없음).

### 배치 결정
- **새 번들 `qa`**(full 전용, 의존 없음). Android/adb 전제라 웹·백엔드 설치처에는 안 깐다.
- **자동제안 대상 아님** — 트리거는 "기기 연결 + QA 착수" 또는 사용자 요청. 자동제안 제외 목록에 추가.
- **Session Protocol ON START에 넣지 않는다**(매 세션 로드 대상이 아니다).
- 플랫폼 일반화(안 2)는 **보류** — 검증된 사례가 안드로이드 하나뿐이라 지금 골격을 짜면 추측이 된다. 스킬 말미에 "다른 플랫폼" 1문단만 두고, iOS·웹 수요가 실제로 생기면 채널 표를 갈아 끼운다.
