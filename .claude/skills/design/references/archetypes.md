# design references — 제품 원형 카드

> design SKILL 1단계 전용. **해당 원형 카드 1~2개만 읽는다** (전체 읽기 금지 — 토큰 낭비이고 위계가 섞인다).
> 카드는 특정 제품의 외형이 아니라 **구조 원리**다. 조합은 최대 2개.

## 원형 고르기 (1분)

| 사용자가 하려는 일 | 원형 |
|---|---|
| 실수 없이 절차를 끝내기 | A1 과업완료형 |
| 뭘 원하는지 모른 채 찾아보기 | A2 발견중심형 |
| 어제 한 걸 오늘 또 하기 | A3 반복실행형 |
| 계속 재생·동기화되는 것을 다루기 | A4 지속상태형 |
| 매일 조금씩 쌓기 | A5 습관형성형 |
| 조건을 좁혀 하나를 확정하기 | A6 조건탐색형 |
| 대량 데이터에서 이상을 찾아 원인 추적 | A7 관측진단형 |
| 콘텐츠 자체를 보여주는 게 전부 | G1 콘텐츠중심 미니멀형 |
| 꾸미기·수집·제작이 많음 | G2 코지 시스템형 |
| 규칙이 단순한 레벨 진행 | G3 에디토리얼 미니멀형 |
| 시간·상태에 따라 할 일이 달라짐 | G4 상태반응형 |
| 짧은 세션을 반복해서 즉시 진입 | G5 액션로비형 |
| 덱·등급·보상 진행이 핵심 | G6 진행루프형 |
| 과제와 자원 제작이 얽힘 | G7 태스크중심형 |
| 이벤트가 많아도 시작 버튼 하나 | G8 원버튼 진행형 |
| 콘텐츠·이벤트가 매우 많음 | G9 고밀도 라이브서비스형 |

각 카드 형식: **핵심 질문 / 3영역 배치 / 우선 토큰 축 / 필수 상태 / 대표 실패**

# A. 앱·도구 원형

## A1 과업완료형
- **핵심 질문**: 사용자가 실수 없이 끝낼 수 있는가?
- **3영역**: 상태=진행 단계와 입력한 값 / 맥락=이번 단계의 질문 1개 / 행동=단일 CTA + 뒤로
- **우선 토큰**: 의미색(오류·주의) > 행동색 > 브랜드색. 중립 표면 + 행동색 하나.
- **필수 상태**: 오류(원인+대안+재시도) · 확인 전 재확인 · 처리 중 중복차단 · 부분 입력 복구
- **설계 규칙**
  - 한 단계에서 **하나의 주요 질문**만 해결한다.
  - 질문을 먼저 쓰고 입력 필드를 나중에 배치한다.
  - 결과 전체를 바꾸는 입력(대상 계정·지역·기간)은 흐름 **초기**에 확인한다.
  - 숫자는 의미 단위와 함께 보여준다 (`3600` ✗ → `3,600 ms (1시간)` ✓).
  - 되돌릴 수 없는 행동은 실행 직전 대상·결과·복구 가능 여부 재확인.
  - 완료 화면은 결과 확인 + 다음 행동으로 끝낸다.
- **대표 실패**: 확정 화면 밀도를 탐색 화면과 같게 만들어 오조작 유발 / 총비용·제약을 마지막에 공개

## A2 발견중심형
- **핵심 질문**: 원하는 걸 몰라도 발견하는가?
- **3영역**: 상태=현재 필터·저장함 / 맥락=이미지 위계가 지배 / 행동=저장 + 다음 탐색
- **우선 토큰**: **콘텐츠가 색을 공급**. UI는 중립 표면 + 최소 액센트.
- **필수 상태**: 이미지 로딩 전 **비율 예약** · 데이터 없음 · 부분 로드 · 저장 완료
- **설계 규칙**
  - 한 화면에 강한 이미지 또는 강한 제목 **하나**만 둔다.
  - 발견 화면과 확정/구매 화면의 정보 밀도를 **다르게** 설계한다.
  - `저장 → 다시 찾기` 경로를 반드시 제공한다. 저장만 되고 못 찾으면 기능이 아니다.
  - 비정형 그리드라도 **읽기 순서와 접근성 순서를 정의**한다.
  - 추천에는 출처 표기 또는 조정 수단을 붙인다.
- **대표 실패**: UI 색이 콘텐츠와 경쟁 / 이미지 비율 미예약으로 스크롤 점프

## A3 반복실행형
- **핵심 질문**: 반복 행동의 비용을 줄였는가?
- **3영역**: 상태=최근 실행·현재 조건 / 맥락=목록 + 빠른 수정 / 행동=재실행 CTA
- **우선 토큰**: 브랜드색을 기능 밀도 안에서 유지. 할인·강조색과 브랜드색을 **같은 역할로 쓰지 않는다**.
- **필수 상태**: 최근 항목 없음 · 조건 변경 중 · 일괄 처리 진행 · 부분 실패
- **설계 규칙**
  - **최근 항목과 재실행을 일급 기능**으로 둔다 (메뉴 깊숙이 넣지 않는다).
  - 수량·옵션 변경을 목록에서 바로 처리하게 한다.
  - 제약(배송 불가, 권한 없음, 재고 없음)은 마지막이 아니라 **탐색 단계부터** 알린다.
  - 합계는 구성요소를 한곳에서 합산해 보여준다.
- **대표 실패**: 2회차 사용자가 1회차와 똑같은 클릭 수를 쓴다

## A4 지속상태형
- **핵심 질문**: 화면을 옮겨도 핵심 상태가 유지되는가?
- **3영역**: 상태=**어디서나 보이는 미니 컨트롤** / 맥락=탐색 화면 / 행동=재생·중단·복귀
- **우선 토큰**: 다크 표면 다단 + 콘텐츠 적응색. 순수 검정 금지, 표면 3단 이상.
- **필수 상태**: 진행 중 · 일시정지 · 버퍼링 · 오프라인 · 실패 후 자동 재시도
- **설계 규칙**
  - 지속 작업(재생·업로드·동기화)은 **화면 이동 후에도 상태와 최소 제어를 남긴다**.
  - 미니 컨트롤을 지나치게 축소해 제어 불가로 만들지 않는다.
  - 개인화 추천에는 이유 또는 조정 수단을 제공한다.
  - 공통 시스템 위에 제품별 확장 레이어를 허용하되 컴포넌트 문법은 공유한다.
- **대표 실패**: 탭 전환에 진행 상태가 사라져 사용자가 처음부터 다시 시작

## A5 습관형성형
- **핵심 질문**: 오늘 시작하고 내일 돌아올 이유가 있는가?
- **3영역**: 상태=현재 위치·완료량 / 맥락=오늘의 최소 목표 하나 / 행동=시작 CTA
- **우선 토큰**: 고채도 다색 허용하되 **의미 고정**(진행·완료·잠금·회복). 색 수보다 역할 일치가 중요.
- **필수 상태**: 잠김 · 진행 중 · 완료 · 끊김 · **회복 수단 제공**
- **설계 규칙**
  - 장기 목표를 **3~5분 안에 끝나는 최소 행동**으로 분해한다.
  - 피드백은 행동 **직후** 제공하고 다음 행동까지 연결한다.
  - 진행 상태에는 현재 위치·완료량·다음 목표가 모두 있어야 한다.
  - 캐릭터·마스코트를 쓴다면 장식이 아니라 **오류·성공·안내를 전달하는 UI 역할**을 준다.
  - 알림 제어권과 회복 수단을 준다. 연속 기록 손실로 압박하지 않는다.
- **대표 실패**: 보상 연출을 UX 설계로 착각 / 끊긴 사용자를 되돌릴 경로 없음

## A6 조건탐색형
- **핵심 질문**: 감성 탐색이 정확한 확정으로 이어지는가?
- **3영역**: 상태=적용된 조건 칩 + 결과 수 / 맥락=목록·지도·비교 / 행동=확정 CTA
- **우선 토큰**: 중립 화면 + 단일 행동색. 선택 상태는 색 + 형태 2채널.
- **필수 상태**: 조건 0건 · 결과 0건(대안 제시) · 조건 충돌 · 확정 전 총비용 노출
- **설계 규칙**
  - **탐색 화면과 확정 화면의 밀도·정보 우선순위를 다르게** 설계한다.
  - 필터 칩은 **선택 상태와 초기화 방법**을 항상 보이게 한다.
  - 두 뷰(목록·지도, 목록·차트)는 선택·필터·스크롤 상태를 **양방향 동기화**한다.
  - 총비용·취소 조건·제약을 **의사결정 전에** 노출한다.
  - 국제화 대상이면 긴 번역·통화·날짜·RTL을 토큰과 레이아웃 단계에서 검증한다.
- **대표 실패**: 조건을 걸어 놓은 걸 잊고 "데이터가 없다"고 오판

## A7 관측진단형
- **핵심 질문**: 지금 데이터가 무엇을 말하고, 다음에 무엇을 파고들어야 하는가?
- **3영역**: 상태=**데이터 범위·최신성·적용 조건·제외 항목** / 맥락=주 지표 1 + 보조 지표 2~4 / 행동=상세 진입 + 근거 추적
- **우선 토큰**: 중립 표면 + 단일 액센트 + **색각 대응 의미색**(성공/주의/위험을 명도로도 구분). 차트 팔레트와 UI 팔레트를 같은 토큰에서 파생.
- **필수 상태**: 데이터 0건 · **부분 데이터**(수집률 낮음) · 갱신 중(옛 결과 오독 차단) · 연결 끊김 · 권한 부족 · 원본 잠금
- **설계 규칙**
  - **적용 중인 조건을 상시 노출**한다. 필터·제외·샘플링은 숨기면 결론을 왜곡한다 — 이 원형의 최대 위험.
  - 지표는 **주 초점 1개**를 크게, 나머지는 보조 크기. 동일 크기 타일 나열은 "무엇부터 볼지"를 사용자에게 떠넘긴다.
  - 모든 수치에 **근거로 가는 경로**를 준다 (집계 → 목록 → 원본).
  - 부분 데이터는 값 옆에 커버리지 배지로 표시한다. 조용히 낮은 값을 보여주면 거짓말이 된다.
  - 도구 표면은 **하는 일 / 상태 / 참고**로 자리를 나누고 섞지 않는다. 자리가 곧 분류다.
  - 반복 조사자를 위해 조건 저장·최근 조회·비교 경로를 둔다.
- **대표 실패**: 툴바에 버튼을 평면 나열해 다음 행동이 안 보임 / 경고색 컨트롤을 상시 노출해 경고 피로

# B. 게임·라이브서비스 원형

> 게임 공통 상수: 홈/로비는 **현재 상태 · 다음 행동 · 기대 보상** 세 질문에 답한다. 이 셋이 다른 화면에 흩어지면 사용자는 로비에서 목적을 다시 찾아야 한다.
> 공통 배치: 상단=상태(프로필·핵심 재화 2~3개) / 중앙=현재 맥락(캐릭터·공간·진행 맵) / 보조=목표·이벤트 / 하단=플레이 CTA + 고정 탭 3~5개.
>
> **조형 언어는 색이 아니라 재질이 만든다.** 게임 UI는 평면 도형이 아니라 **덩어리(volume)**로 그린다 — 아웃라인·상단 광택·본체 그라디언트·하단 립·하드 드롭 5층이 모든 표면에 같은 순서로 쌓이고, 광원 방향은 화면 전체가 하나다. 색 토큰만 맞추고 이 축을 빼면 "디자인이 안 입혀진 화면"이 된다. 그래픽 컨셉은 **사용자에게 물어 확정**하고(SKILL 2-G), 컨셉은 스킨 토큰만 바꾼다 — 재질·레이아웃·컴포넌트는 불변. 상세: `.claude/skills/design/references/tokens.md` 게임 그래픽 컨셉 절.

## G1 콘텐츠중심 미니멀형
- **핵심 질문**: 콘텐츠 자체가 화면의 주인공인가?
- **배치**: 중앙에 콘텐츠 하나를 크게, UI 표면은 **후퇴**(중립·저채도)
- **우선 토큰**: 표면 중립 + 콘텐츠가 색 공급. 액센트 1개.
- **필수 상태**: 대기(시간·진행도·가능 여부 동시 표시) · 신규 · 획득 완료
- **설계 규칙**: 콘텐츠가 강하면 UI는 중립 / 홈에서 가장 기대되는 행동 하나만 가장 크게 / 영구=하단 탭, 일시=홈 카드
- **대표 실패**: 이벤트 카드가 늘면서 미니멀 구조 붕괴 → 진입점 상한을 미리 정한다

## G2 코지 시스템형
- **핵심 질문**: 기능이 많은데도 친근하게 읽히는가?
- **배치**: 기능 다수를 **동일한 카탈로그 문법**으로 통합
- **우선 토큰**: 검정 대신 **짙은 브랜드 중성색**. 저채도 고명도 표면.
- **필수 상태**: 잠금 · 재료 부족 · 제작 중 · 완료 수령
- **설계 규칙**: 복잡한 기능을 같은 카드 문법으로 / 아이콘 최초 노출 시 텍스트 라벨 병기 / 코지 톤에서도 잠금·부족·완료를 명확히 구분
- **대표 실패**: 아이콘만 남겨 신규 사용자 학습 비용 폭증

## G3 에디토리얼 미니멀형
- **핵심 질문**: 색 없이도 정체성이 있는가?
- **배치**: 여백·선·소수 색만으로 구성. 이벤트는 기본 내비와 **분리**.
- **우선 토큰**: 색 2~3개. 반복되는 **조형 규칙**(선 두께·radius·여백 리듬)이 브랜드를 만든다.
- **필수 상태**: 진행 중 · 완료 · 재도전
- **설계 규칙**: 색 수가 아니라 반복 조형이 브랜드 / 시각 초점 1개 / 여백은 남는 공간이 아니라 위계 요소
- **대표 실패**: 라이브 이벤트가 늘며 미니멀 구조 약화 → 이벤트를 별도 표면에 격리

## G4 상태반응형
- **핵심 질문**: 시간·상태에 따라 같은 홈이 다른 우선순위를 보이는가?
- **배치**: 동일 홈, **시간대/진행 상태에 따라 주 CTA 교체**
- **우선 토큰**: 상태별 표면 톤 세트(예: 준비·진행·결과). 톤이 바뀌어도 컴포넌트 문법은 불변.
- **필수 상태**: 준비 전 · 진행 중 · 결과 · 중단 · 재개
- **설계 규칙**: 중요한 루틴은 **시작 전 설정과 실행 상태를 분리** / 감성 연출에 반복 사용자용 단축 경로 / 데이터·보상·캐릭터가 한 화면에서 경쟁하지 않게
- **대표 실패**: 핵심 작업 전 단계와 연출이 길어져 매일 하는 행동이 느려짐

## G5 액션로비형
- **핵심 질문**: 고밀도 화면에서도 플레이 CTA가 살아 있는가?
- **배치**: **기능별 고정 구역**을 먼저 정하고 그 안에서만 콘텐츠 교체
- **우선 토큰**: 강한 액센트 1개를 플레이에 독점 배정. 나머지는 채도 억제.
- **필수 상태**: 선택된 콘텐츠 표시 · 매칭 중 · 알림 등급 3종
- **설계 규칙**: 고정 구역 우선 / 핵심 CTA는 크기·위치·색 **셋 다** 사용 / 플레이 버튼 옆에 현재 선택 맥락 표시 / 알림은 중요도 등급 + 개수 상한
- **대표 실패**: 가장자리 아이콘 과밀 → 진입점 상한 규칙 필요

## G6 진행루프형
- **핵심 질문**: 메타 진행과 코어 플레이가 같은 화면에서 이어지는가?
- **배치**: 플레이 · 보상 · 성장을 한 화면에서 연결
- **우선 토큰**: 등급/희소도 색 축을 별도로 두되 **행동색보다 강해지지 않게** 제한.
- **필수 상태**: 진행도 · 수령 가능 · 수령 완료 · 잠금
- **설계 규칙**: 메타 진행과 코어 플레이 관계를 같은 화면에 / 추상적 숫자는 세계관 오브젝트로 시각화 가능 / 경쟁 색상은 상태 의미와 일치하게 반복 / **상품 프로모션이 플레이 CTA보다 강해지지 않게**
- **대표 실패**: 상점·패스가 코어 CTA와 시각적으로 경쟁

## G7 태스크중심형
- **핵심 질문**: 목표에서 실행 위치까지 바로 갈 수 있는가?
- **배치**: 목표 카드 리스트 + 실행 진입
- **우선 토큰**: 카드 표면 3종(메인·반복·이벤트)으로 과제 종류 구분.
- **필수 상태**: 진행 전 · 진행 중 · 완료 · 수령
- **설계 규칙**: 목표 카드는 **제목 → 요구 조건 → 보상 → 행동** 순서 고정 / 과제에서 실행 위치로 직접 이동 / 메인·반복·이벤트를 표면 또는 헤더로 구분 / 유사 아이템에 이미지 외 텍스트·단계 표시
- **대표 실패**: 이벤트 과제와 메인 과제 구분이 흐려져 무엇이 사라질지 모름

## G8 원버튼 진행형
- **핵심 질문**: 이벤트가 아무리 많아도 시작 버튼이 그대로인가?
- **배치**: 화면 하단 중앙 고정 **단일 시작 CTA**, 주변에 이벤트 진입점
- **우선 토큰**: 프리미엄 표현(광택·금색)은 **제한된 영역에만**. 전면 사용 시 카지노형 인상.
- **필수 상태**: 시작 가능 · 자원 부족 · 실패 후 재도전 · 보상 수령
- **설계 규칙**: 이벤트가 많아도 **핵심 CTA의 크기와 위치를 양보하지 않는다** / 보상 팝업의 정보 순서와 버튼 위치 고정 / 이벤트 진입점 동시 노출 수 제한 또는 묶음 메뉴
- **대표 실패**: 실패 화면에서 구매만 제시하고 획득 경로를 안 준다

## G9 고밀도 라이브서비스형
- **핵심 질문**: 콘텐츠가 계속 늘어도 기본 구조가 버티는가?
- **배치**: **위치 규칙을 테마보다 먼저** 확정. 신규 콘텐츠는 기존 패널에 들어간다.
- **우선 토큰**: 공통 조형 언어(radius·테두리·그림자·버튼 패밀리) 단일. 시즌 테마는 **스킨 레이어**로만.
- **필수 상태**: 신규 · 진행 중 · 만료 임박 · 종료 · 잠금
- **설계 규칙**: 위치 규칙 우선 / 신규 콘텐츠는 공통 패널·버튼 구조 안에서 **스킨만 변경** / 배지는 즉시 처리 가능한 항목에만 / 초기에는 잠긴 기능을 숨기거나 단계 공개 / **시즌 테마가 기본 내비의 위치와 형태를 바꾸지 않는다** / 만료된 이벤트가 사라져도 빈 공간이 생기지 않게
- **대표 실패**: 이벤트마다 새 버튼 디자인 → 시스템 일관성 붕괴, 신규 사용자 인지 부하
