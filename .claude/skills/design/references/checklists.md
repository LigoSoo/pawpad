# design references — 상태 매트릭스 · 최악조건 · 안티패턴

> design SKILL 5·6단계 전용. 필요한 절만 부분 읽기.

---

## 1. 상태 매트릭스

핵심 컴포넌트마다 아래 칸을 채운다. **해당 없으면 `n/a` + 사유** — 빈칸을 남긴 채 완료 선언 금지.

| 상태 | 확인할 것 |
|---|---|
| 기본 | 아무 일도 없을 때의 모습 |
| 눌림·포커스 | 키보드 focus ring이 보이나. 마우스와 키보드 둘 다 |
| 선택 | 색 + 형태 2채널로 구분되나 |
| 로딩 | 스켈레톤/스피너/진행도 중 무엇. 중복 실행 차단되나 |
| 완료 | 결과 확인 + **다음 행동**까지 주나 |
| 비활성 | 왜 비활성인지 알 수 있나 |
| 오류 | 원인 + 현재 상태 + 대안 + 재시도 4요소 |
| **데이터 없음** | 처음부터 없음 / 조건 때문에 없음을 구분하나 |
| **부분 데이터** | 일부만 수집·로드된 상태를 값 옆에 표시하나 |
| **지연·오프라인** | 느린 네트워크와 끊김을 실패와 다른 언어로 표현하나 |
| **권한 거부** | 무엇이 필요하고 어디서 켜는지 안내하나 |
| 표시환경 | 큰 글자(200%) · 화면 회전 · 다크 모드에서 깨지지 않나 |

게임·라이브서비스 추가 상태: **잠금 · 자원 부족 · 수령 가능 · 수령 완료 · 만료 임박 · 종료 · 신규**

### 컴포넌트별 필수 상태 (게임)
| 컴포넌트 | 필수 상태 | 규칙 |
|---|---|---|
| 주 CTA | 기본·누름·로딩·비활성 | 화면당 핵심 행동 1개에만 |
| 보조 버튼 | 기본·누름·비활성 | 취소가 아닌 **대안 행동** |
| 내비 탭 | 기본·선택·알림·잠금 | 선택은 색 + 형태 동시 변경 |
| 자원 카운터 | 정상·부족·증가·감소 | 아이콘·수량·증감 연출 고정 |
| 목표 카드 | 진행 전·진행 중·완료·수령 | 제목→조건→보상→행동 순서 고정 |
| 보상 카드 | 잠금·수령 가능·수령 완료 | 가치와 수령 가능 상태를 분리 |
| 이벤트 진입점 | 신규·진행 중·만료 임박·종료 | 타이머와 배지를 같은 위치에 |
| 모달 | 정보·확인·보상·오류 | 제목→내용→행동 순서 불변 |
| 배지 | 신규·수령 가능·긴급 | 단순 미열람과 행동 필요를 구분 |

### 배지·알림 정책
- **빨간 점**: 새 콘텐츠는 있으나 즉시 행동 불필요
- **숫자 배지**: 처리 가능한 항목 수가 의사결정에 필요할 때만
- **선물·체크 아이콘**: 즉시 수령 가능
- **타이머**: 만료·회복 시간이 실제 판단에 필요할 때만
- 한 화면의 **강한 배지 최대 3개**. 전부 빨간 배지면 아무것도 중요하지 않다.
- **계수 단위**: 화면에 동시에 보이는 것을 **위치 무관하게 합산**한다 — 탭 배지·카드 pill·이벤트 flag·리스트 항목 배지가 전부 1개씩이다. "탭은 따로 센다" 같은 예외를 두면 상한이 무력해진다. 약한 표시(빨간 점)는 별도로 세되 화면당 3개 이내로 둔다.

### 실패·부족 상태 규칙
- 실패 원인과 다음 선택을 **분리**한다.
- 자원 부족 시 구매만 제시하지 말고 **획득 경로**도 준다.
- 실패 직후 주 CTA는 `재시도`, 보조는 `나가기`. 순서를 바꾸지 않는다.
- 파괴적 행동에는 결과와 **복구 가능 여부**를 명시한다.
- 네트워크 오류는 작업 실패와 **다른 시각 언어**를 쓴다.

## 2. 최악 조건 검증 (구현 후 2nd pass)

> ⚠ **폭 × 상태의 곱으로 돌린다.** 최소 폭을 기본 상태에서만 보면 못 잡는다 — 자원 부족·오류·부분 데이터처럼 **텍스트가 늘어나는 상태**와 겹칠 때 넘친다. 최소 폭 × (기본 / 가장 긴 상태) 조합을 각각 확인한다.

- [ ] **최소 폭**(모바일 320px / 데스크톱 프로젝트 최소 창)에서 **가장 긴 한국어 라벨**이 안 잘리나
- [ ] 시스템 글자 **200% 확대**에서 레이아웃이 유지되나
- [ ] **흑백 렌더**에서 완료·잠금·오류·선택 상태가 구분되나
- [ ] 데이터 **0건**과 데이터 **과다**(목록 1000행, 이벤트 10개) 양쪽에서 무너지지 않나
- [ ] 이미지가 **없을 때**·비율이 다를 때 카드가 깨지지 않나
- [ ] 느린 네트워크 + **중복 탭**에서 요청이 두 번 나가지 않나
- [ ] 다크 모드에서 표면 단계·대비·이미지 명도가 다시 검증됐나
- [ ] 키보드 노출·안전 영역(모바일) / 창 최소화·최대화(데스크톱)
- [ ] 다국어 번역이 길어질 때 버튼과 탭이 안 넘치나. 숫자·날짜 지역 형식
- [ ] 키보드만으로 전 기능에 도달하나. 읽기 순서와 접근성 라벨이 정의됐나

## 3. 안티패턴

### 3.1 공통 (전 원형)
| 안티패턴 | 문제 | 개선 |
|---|---|---|
| 전 화면 그라디언트·글래스모피즘·과도한 그림자 | 위계가 사라지고 대비가 깨짐 | elevation 토큰 단계로만 |
| "세련됨"을 이유로 본문 대비·글자 크기 낮춤 | 접근성 실패 | AA 4.5:1 고정 |
| 여러 레퍼런스의 색·컴포넌트를 목적 없이 혼합 | 문법 붕괴 | 원형 최대 2개 조합 |
| 홈에 가능한 모든 기능을 카드로 나열 | 다음 행동이 안 보임 | 주 CTA 1개 + 나머지 강등 |
| 동일 강조도 주 CTA 2개 이상 | 사용자가 선택 비용 부담 | 강조도 차등 |
| 로딩·오류·빈 상태 없이 정상 화면만 생성 | 실제 운영 조건에서 붕괴 | 상태 매트릭스 |
| 색만으로 잠금·완료·오류 표현 | 색각 차이·흑백 출력 | 2채널 이상 |
| 아이콘만 쓰고 라벨 제거 | 학습 비용 | 최초 노출·핵심 메뉴엔 라벨 병기 |
| 닫기·확인 위치가 화면마다 다름 | 오조작 | 유형별 표준화 |
| 총비용·취소·삭제·권한 조건을 마지막에 공개 | 신뢰 손상 | 의사결정 **전** 노출 |
| 긴급성·희소성·연속기록 손실로 압박 | 다크패턴 | 정보만 제공, 압박 금지 |
| 플랫폼 관습 무시하고 픽셀 단위 동일화 | 관습 위배 | 공통 컴포넌트 + 플랫폼 내비 유지 |
| 고유 로고·캐릭터·카피·아이콘 복제 | 권리 문제 | 구조 원리만 차용 |

### 3.2 앱·도구
| 안티패턴 | 개선 |
|---|---|
| 캐릭터·모션을 추가하고 이를 UX 설계로 착각 | 캐릭터에 오류·성공·안내 **역할**을 부여하거나 뺀다 |
| 탐색 화면과 확정 화면의 밀도가 같음 | 확정 화면은 밀도를 낮추고 초점을 좁힌다 |
| 이미지 비율 미예약으로 로드 시 스크롤 점프 | 로딩 전 비율 예약 |
| 저장은 되는데 다시 찾을 경로가 없음 | 저장 → 재발견 구조 |
| 적용 중인 필터·제외를 숨김 | 활성 조건 상시 노출 + 초기화 경로 |
| 브랜드색과 할인·강조색을 같은 역할로 사용 | 역할 분리 |
| 툴바에 버튼 평면 나열 | 하는 일 / 상태 / 참고로 자리를 나눔 |

### 3.3 게임·라이브서비스
| 안티패턴 | 문제 | 개선 |
|---|---|---|
| 모든 메뉴에 빨간 배지 | 중요도 구분 불가, 알림 피로 | 즉시 처리 가능한 항목만 강한 배지 |
| 상점 CTA가 플레이 CTA보다 큼 | 게임 목적보다 과금이 먼저 | 플레이 CTA 크기·위치 우선 |
| 이벤트마다 완전히 다른 버튼 디자인 | 시스템 일관성 붕괴 | 공통 컴포넌트에 **스킨만** |
| 보상 팝업을 여러 단계로 반복 | 흐름 단절·피로 | 일괄 수령·요약 화면 |
| 홈에서 모든 재화 표시 | 인지 부하 | 현재 행동 관련 2~3개만 |
| 반복 사용에도 애니메이션 강제 | 작업 시간 증가 | 건너뛰기·단축 연출 |
| 시즌 테마가 기본 내비 위치·형태를 변경 | 위치 기억 붕괴 | 테마는 표면·색만 |
| 만료 이벤트가 사라지며 빈 공간 발생 | 레이아웃 붕괴 | 영구/임시 영역 분리 |
| 프리미엄 표현(광택·금색) 전면 사용 | 카지노형 인상 | 제한 영역에만 |

## 4. 최종 체크리스트 (완료 직전 1회)

### 위계
- [ ] 첫 3초에 **지금 상태 / 다음 행동 / 기대 결과**가 읽히나
- [ ] 주 초점 1개 · 주 CTA 1개인가
- [ ] 제목·핵심 값·설명·메타데이터 4단이 구분되나
- [ ] 위계 수단이 한 번에 2개 이내인가
- [ ] 카드·구분선을 줄이고 여백으로 그룹을 표현했나
- [ ] 영구 기능과 임시 기능이 위치상 구분되나. 임시가 없어져도 레이아웃이 버티나

### 재질 (게임·캐주얼 전용)
- [ ] 모든 표면이 **같은 5층**을 같은 순서로 쌓나 (아웃라인→광택→본체→립→하드드롭)
- [ ] **광원 방향이 화면 전체에 하나**인가
- [ ] 재질 강도가 위계를 따르나 — 주 CTA가 가장 강하고 상품·보조는 한 단계 낮은가
- [ ] 진행바 트랙·선택된 탭이 **파여** 있고 채움·비선택이 볼록한가
- [ ] 배경 아트 위 텍스트에 **아웃라인 스트로크**가 있나
- [ ] **컨셉 교체가 스킨 토큰 값 변경만으로 끝나나** (셀렉터·레이아웃·컴포넌트 추가 0건)

### 일관성
- [ ] spacing 임의값 0건, radius 고유값 ≤4, 컨트롤 높이 고유값 ≤3
- [ ] shadow가 elevation 토큰 밖 0건, 하드코딩 색상 0건
- [ ] 같은 역할 컴포넌트가 모든 화면에서 동일하게 보이나
- [ ] 신규 콘텐츠·이벤트가 기존 컴포넌트 스킨으로 처리되나

### 색·타이포
- [ ] 브랜드색·행동색·의미색의 역할이 충돌하지 않나
- [ ] 대비 AA(4.5:1) 라이트·다크 양쪽 충족
- [ ] 색 없이도 상태를 구분할 수 있나
- [ ] 한국어 줄바꿈·숫자 자릿수·단위 표기가 안정적인가
- [ ] 다크가 단순 반전이 아닌 별도 표면 체계인가

### UX
- [ ] 한 단계에서 하나의 주요 질문만 묻나
- [ ] 되돌릴 수 없는 행동 전에 결과를 확인시키나
- [ ] 실패 후 복구 경로가 있나
- [ ] 반복 사용자 단축 경로가 있나
- [ ] 화면 이동 후에도 중요한 상태가 보존되나
- [ ] 비용·제약·제외·부분 데이터가 늦게 드러나지 않나

### 모션·피드백
- [ ] 탭·선택·저장·확정에 즉시 피드백이 있나
- [ ] 모션이 상태 변화 또는 공간 관계를 **설명**하나
- [ ] `prefers-reduced-motion`에서 정보 손실이 없나
- [ ] 처리 중 중복 실행이 차단되나

### 시스템화
- [ ] 색·타이포가 의미 기반 토큰으로 정의됐나
- [ ] 컴포넌트별 최대 구성과 최악 조건이 문서화됐나
- [ ] 상태 매트릭스에 빈칸이 없나 (`n/a` + 사유 포함)
- [ ] 공통 foundation과 제품별 확장 영역이 구분되나
