# design references — 의미 기반 토큰 시작안

> design SKILL 2단계 전용. **기존 프로젝트에는 이 값을 덮어쓰지 않는다** — 프로젝트 토큰이 소스이고, 이 파일은 신규 부트스트랩과 누락 축 보강용 참고다.
> 값보다 **이름의 의미**가 중요하다. `blue500`이 아니라 `action.primary`, `gray700`이 아니라 `text.secondary`여야 테마 교체와 접근성 조정이 이름 하나로 끝난다.

## 색 — 정의 순서를 지킨다

표면 → 텍스트 → 경계 → 의미색 → 행동색 → 브랜드색.
브랜드색을 먼저 잡으면 의미색이 브랜드색에 밀려 상태가 안 읽힌다.

```yaml
color:
  surface:
    base:      "#F7F8FA"   # 앱 배경
    raised:    "#FFFFFF"   # 카드·패널
    sunken:    "#EEF0F3"   # 입력·코드·표 헤더
    overlay:   "rgba(0,0,0,0.45)"  # 모달 뒤 딤
    disabled:  "#F1F3F5"
  text:
    primary:   "#191F28"
    secondary: "#4E5968"
    tertiary:  "#8B95A1"
    inverse:   "#FFFFFF"
  border:
    subtle:    "#E5E8EB"
    strong:    "#B0B8C1"
    focus:     "행동색과 구분되는 값 — focus ring은 상태색이 아니다"
  semantic:
    success:   "#1F9D61"
    warning:   "#D97706"
    danger:    "#D64545"
    info:      "#2563EB"
  action:
    primary:         "브랜드에 맞게 결정 — 화면당 한 의미로만"
    primary_pressed: "명도 또는 채도를 한 단계 낮춤"
    secondary:       "표면 + 경계선. 채우지 않는다"
    tertiary:        "텍스트 링크 수준"
    disabled:        "#D1D6DB"
```

게임·라이브서비스면 두 축을 **추가**한다. 기존 축을 대체하지 않는다.

```yaml
  economy:
    soft:      "일반 재화"
    premium:   "유료·희귀 재화"   # action.primary보다 강해지지 않게 제한
    energy:    "플레이 가능 횟수"
  rarity:
    common: / rare: / epic: / legendary:
```

게임은 여기에 **HUD 미세 층**도 필요하다. 타입 스케일이 12px에서 끝나고 컨트롤 높이가 32~40부터 시작하면 배지·플래그·재화 칩이 스케일 밖으로 샌다. 터치 타깃 규칙(≥44)은 터치 요소만 덮는다.

```yaml
spacing:   { 0.5: 2 }                 # 반 단계 — HUD는 4px 격자보다 촘촘한 층이 있다
font:      { micro: 10 }              # HUD 라벨
indicator: { sm: 16~18, md: 22~24 }   # 비터치 표시 요소 — 컨트롤 높이와 별개 축
```

### 색 사용 규칙
- 화면 배분 시작점: **표면 70 / 브랜드·강조 표면 20 / 행동·상태 10**.
- 핵심 CTA 색은 한 화면에서 **하나의 의미로만** 쓴다.
- 위험색을 단순 알림 배지와 파괴적 행동에 **같이** 쓰지 않는다.
- 브랜드색·성공색·선택색이 같은 값이면 형태와 텍스트로 의미를 보완한다.
- 색 외에 **아이콘·텍스트·형태 중 하나를 중복**시킨다 (색 단독 전달 0건).
- 색각 차이를 고려하면 성공/주의/위험을 **명도로도 구분**되게 고른다 — 흑백 렌더 테스트로 검증.
- 배경 일러스트·이미지 위의 UI는 표면 대비 또는 외곽선을 강화한다.

### 다크는 반전이 아니다
| 재정의 대상 | 규칙 |
|---|---|
| 표면 | 순수 검정 금지. `base < raised < sunken` **3단 이상**을 명도로 다시 정의 |
| 그림자 | 다크에서는 그림자가 안 보인다 — **경계선 또는 표면 명도차**로 대체 |
| 이미지 | 밝은 이미지는 명도를 낮추거나 오버레이. 흰 배경 이미지가 그대로 뜨면 눈이 아프다 |
| 상태색 | 라이트 값 그대로 쓰면 대비가 깨진다. 배경 대비 4.5:1 재검증 |
| 액센트 | 다크에서는 채도를 낮추고 명도를 올린다 |
| 액센트 위 텍스트 | 밝은 액센트 위에 흰 글자는 대비 미달. **어두운 전경색**을 별도 토큰으로 |

## 게임 그래픽 컨셉 — SKILL 2-G 게이트 전용

게임 UI는 색·간격 토큰만으로는 **디자인이 안 입혀진 화면**이 된다. 토큰을 쓰기 전에 컨셉을 사용자에게 묻고 확정한다(에이전트가 임의로 고르지 않는다).

### 컨셉 카드 형식 (6항 전부 채운다)
| 항목 | 예 |
|---|---|
| 소재 | 나무·대나무 / 석재·금속 / 젤리·캔디 / 종이·펠트 / 수정·마법 |
| 아웃라인 | 두꺼운 어두운 선(카툰) / 얇은 선 / 없음(소프트) |
| 광원 | 위에서 아래 (화면 전체가 **하나의 방향**) |
| 팔레트 | 표면 2단 + 액센트 1 + 강조 1 (3~4색) |
| 장식 모티프 | 잎·덩굴 / 볼트·리벳 / 리본·별 / 물방울 |
| 대표 실패 | 이 컨셉이 무너지는 지점 (예: 배경 아트와 채도가 겹쳐 UI가 묻힘) |

### 프리셋 3종 (AskUserQuestion 옵션으로 제시 + 사용자 자유 입력 허용)
| 컨셉 | 소재 · 아웃라인 | 팔레트 성격 | 대표 실패 |
|---|---|---|---|
| **자연·목재** | 나무/대나무 · 두꺼운 갈색 아웃라인 | 갈색 표면 + 잎 초록 + 주황 CTA | 배경이 초록이면 CTA가 보색 하나뿐이라 선택지가 좁다 |
| **캔디·젤리** | 반투명 젤리 · 두꺼운 흰 아웃라인 | 고채도 파스텔 다색 + 흰 하이라이트 | 색이 많아 의미색(성공/위험)이 장식에 묻힌다 |
| **수정·마법** | 유리/수정 · 발광 테두리 | 어두운 표면 + 청보라 발광 + 금색 강조 | 발광을 남발하면 주 CTA 강조가 사라진다 |

### 재질 축 — 5층을 항상 같은 순서로
컨셉이 무엇이든 **층의 순서와 개수는 고정**이다. 컨셉은 값만 바꾼다.

```yaml
material:                       # --mat-* : 컨셉과 무관하게 불변
  1_outline: "2~3px 어두운 단색. 배경 아트 위에서 요소를 떼어낸다"
  2_rim:     "inset 0 2px 0 rgba(255,255,255,.4~.6) — 상단 광택. 광원 방향 고정"
  3_body:    "세로 그라디언트 (밝음 → 어둠)"
  4_lip:     "inset 0 -4~5px 0 rgba(0,0,0,.18~.24) — 두께감. 눌리면 줄어든다"
  5_drop:    "0 3~4px 0 rgba(0,0,0,.25) — blur 0. 흐린 그림자는 앱, 단단한 그림자는 게임"
  inset:     "inset 0 3px 5px rgba(0,0,0,.3) — 홈 파인 트랙(진행바·선택된 탭)"
  stroke:    "텍스트 4방향 아웃라인 — 배경 아트 위 글자는 스트로크가 없으면 못 읽는다"

skin:                           # --sk-* : 컨셉이 채운다. 테마 교체 = 이 값만 교체
  edge:      "공통 아웃라인색"
  surface_1 / surface_2: "패널 그라디언트 2단"
  accent_1 / accent_2:   "리본·탭 등 액센트 2단"
```

### 재질 규칙 4개
- **광원은 화면 전체가 하나.** 어떤 요소는 위가 밝고 어떤 요소는 아래가 밝으면 즉시 아마추어로 읽힌다.
- **오버행**: 헤더 리본은 패널 **밖으로**, 재화 아이콘은 알약 **밖으로** 나간다. 전부 사각형 안에 넣으면 앱이 된다.
- **재질 강도가 곧 위계**: 주 CTA가 광택·립·드롭이 가장 강하고, 상품·보조 요소는 한 단계 낮춘다. 크기·위치·색에 이은 **네 번째 강조 수단**이다.
- **홈은 파이고 채움은 볼록**: 진행바 트랙·선택된 탭은 `inset`, 채움·비선택은 볼록.

### 컨셉 교체 검증 (완료 조건)
컨셉을 바꿔 봤을 때 **`--sk-*` 값 변경만**으로 끝나야 한다. 셀렉터 추가·레이아웃 변경·컴포넌트 신설이 필요하면 그건 컨셉이 아니라 **리디자인**이고, 시즌 테마가 늘어날수록 시스템이 무너진다(G9 "이벤트마다 다른 버튼" 안티패턴과 동형).

## 간격 — 4px 베이스 단일 스케일

```yaml
spacing: { 0:0, 1:4, 2:8, 3:12, 4:16, 5:20, 6:24, 8:32, 10:40, 12:48 }
```
- 컴포넌트 내부 < 요소 간 < 섹션 간 — 세 단계가 구분돼야 그룹이 읽힌다.
- 수직 리듬을 일정하게. 임의값(13px, 17px) 0건.

## 크기 — 컨트롤 높이와 아이콘

```yaml
control_height: { sm:32, md:40, lg:48 }   # 데스크톱은 sm:28 / md:32 / lg:40도 가능
icon:           { sm:16, md:20, lg:24 }
touch_target:   { minimum:44 }            # 터치 환경. 마우스 전용이면 32까지
```
- 같은 위계의 버튼·인풋·셀렉트는 **같은 높이**. 고유값 ≤3.

## 모양

```yaml
radius:  { control:10, card:16, sheet:24, pill:999 }   # 데스크톱은 control:4 / card:6 등 작게
border:  { width:1 }
elevation: { e1:"낮음 — 카드", e2:"중간 — 팝오버", e3:"높음 — 모달" }
```
- radius 고유값 ≤4. 카드/버튼/인풋/모달 혼용 금지.
- shadow는 elevation 단계 밖의 값 0건.

## 타이포그래피 — 폰트 종류보다 역할

```yaml
typography:
  display: { size:32, weight:700, line_height:1.25 }
  title_1: { size:24, weight:700, line_height:1.30 }
  title_2: { size:20, weight:700, line_height:1.35 }
  body_1:  { size:16, weight:400, line_height:1.50 }
  body_2:  { size:14, weight:400, line_height:1.50 }
  caption: { size:12, weight:400, line_height:1.40 }
```
- 역할·크기·굵기·줄높이·**줄 수 제한**까지 토큰화한다. 줄 수를 안 정하면 긴 제목이 카드를 깬다.
- **한국어는 같은 크기 영문보다 시각 밀도가 높다** — 줄높이를 여유 있게, 버튼 폭을 넉넉히.
- 숫자 중심 화면은 금액·시간·퍼센트의 **단위 정렬과 자릿수 변화**를 검증한다 (등폭 숫자 권장).
- 텍스트 위계 최소 4단: 제목 · 핵심 값 · 설명 · 메타데이터.

## 모션 — 역할 위계가 값보다 먼저

우선순위: **피드백 → 공간 관계 설명 → 상태 변화 → 브랜드 장식.** 아래로 갈수록 없어도 된다.

```yaml
motion:
  instant:    100   # 눌림·토글 피드백
  quick:      180   # 호버·포커스·작은 전환
  standard:   260   # 패널·시트 열림
  emphasized: 360   # 중요한 완료·보상
```
- 반복 조작은 짧게, 중요한 완료만 상대적으로 강하게.
- **로딩을 숨기려는 애니메이션 금지.** 대기는 진행도로 표현한다.
- 반복 연출에는 **건너뛰기 또는 단축 경로**를 준다.
- `prefers-reduced-motion`에서도 정보가 손실되지 않아야 한다 (모션이 유일한 상태 전달 수단이면 위반).

## 브레이크포인트

```yaml
breakpoint: { mobile: "<600", tablet: "600-1024", desktop: ">1024" }
```
데스크톱 앱은 프로젝트 최소 창 폭 기준으로 narrow/compact/wide 3단을 따로 정의한다. 고정 px 레이아웃은 지양.

**게임은 breakpoint를 쓰지 않는다.** 방향(portrait/landscape)이 고정이고 창 크기가 바뀌지 않기 때문이다. 대신 이 셋을 잡는다.

```yaml
orientation: "portrait | landscape"   # 고정. 둘 다 지원하면 사실상 화면 2벌이다
safe_area:   "노치·홈 인디케이터·펀치홀 여백 — 상태/행동 영역이 여기 물리면 안 된다"
min_frame:   "가장 좁은 폭 × 가장 낮은 높이 (예: 320 × 568)"
```
- **세로형**은 상·중·하 계층을, **가로형**은 좌·우 구역을 먼저 나눈다.
- 화면비가 길어지면(19.5:9 등) **중앙 맥락 영역이 늘어나고 상태·행동 영역은 고정**이다. 그 반대로 설계하면 긴 화면에서 CTA가 떠오른다.

## 스택별 토큰 위치 (참고)
| 스택 | 위치 |
|---|---|
| 웹/CSS | `:root` CSS 변수 + 다크는 `prefers-color-scheme` / `[data-theme]` |
| Tailwind | `theme.extend` — 임의값(`p-[17px]`) 금지 |
| Flutter | `ThemeData` + `ThemeExtension` |
| WPF | `ResourceDictionary` (`DynamicResource`로 라이브 테마 교체) |
| React Native | 단일 `tokens.ts` + Provider |

토큰을 정의했으면 **이후 raw 값 작성 금지**. 새 값이 필요하면 토큰을 추가하고 그 토큰을 참조한다.
